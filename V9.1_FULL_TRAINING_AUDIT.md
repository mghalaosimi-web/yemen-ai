# Yemen AI v9.1 — Full Training & Intelligence Audit

## Executive finding
The main weakness was architectural, not merely lack of seed files. Several paths labeled as "training" only chunked files and inserted vectors. In particular, manually added knowledge was stored in SQLite but was not indexed into the RAG store, so the chat engine could not reliably use it. Retrieval also depended on a very small hash embedding with weak Arabic normalization and no training artifacts.

## Root causes found
1. Manual knowledge and chat knowledge paths were inconsistent.
2. "Training completed" measured chunks, not whether knowledge became answerable.
3. Embeddings were 256-dimensional token hashes with weak tolerance for Arabic morphology, spelling variation and paraphrases.
4. Retrieval used simple overlap plus cosine and did not reward rare technical terms sufficiently.
5. No explicit post-ingestion knowledge cards existed to convert dense source text into compact question-answer evidence.
6. Existing tests mainly validated endpoint success and did not sufficiently test learning behavior after ingestion.

## Fixes in v9.1
- Added an explicit offline training pipeline.
- Pipeline stages: normalize -> smart chunk -> index -> concept capture -> QA-card generation -> retrieval-ready.
- Manual knowledge now indexes immediately into the same retrieval store used by chat.
- Rebuilt embeddings to 768 dimensions using normalized word, word-bigram and character-trigram features.
- Added Arabic normalization and typo/morphology resilience at embedding level.
- Replaced simple lexical blending with an IDF-weighted hybrid ranker.
- Generated compact retrieval cards from informative sentences after training.
- Added targeted tests for paraphrase/English alias recall and QA-card generation.

## Validation
- Python compilation: successful.
- Full automated suite: 62 passed.

## Important limitation
This remains an offline retrieval-and-reasoning system, not a large pretrained generative language model. These changes fix the broken learning path and substantially improve usable knowledge recall, but they cannot by themselves create ChatGPT-level open-domain language generation. The system should therefore remain evidence-first and abstain when knowledge is missing.
